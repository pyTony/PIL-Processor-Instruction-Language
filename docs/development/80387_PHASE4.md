# 80387 phase 4: division, ordered comparison, m80

This phase extends the explicit **opt-in** 80387 backend. The default
PILdos machine remains without an installed numeric coprocessor.

Run a DOS session with `--fpu 80387` (or use the session command `fpu
80387` before the first guest instruction). The implementation uses integer
arithmetic; no host floating point, Rust `f32`, or Rust `f64` is used
for 80-bit division or comparisons.

## Implemented subset

* `FDIV`, `FDIVR`, `FDIVP`, `FDIVRP` on the supported register encodings.
* `FDIV`/`FDIVR` with IEEE binary32 and binary64 memory operands.
* `FCOM ST(i)`, `FCOMP ST(i)`, `FCOMPP` and `FCOM`/`FCOMP`
  with IEEE binary32/binary64 memory operands.
  C0=1 means less, C3=1 means equal; greater clears C0/C2/C3.
  The comparisons do not alter CPU FLAGS. C1 is reset on success.
* `FLD m80` and `FSTP m80` for exact 10-byte extended-real transfers
  (DB /5 and DB /7), preserving signed zero, finite normal values and
  infinities. Memory/segment checks precede writes; a refused store does
  not pop ST(0).
* Division uses a 128-bit integer numerator, exact remainder, and
  nearest-even rounding of the 64-bit significand.
* Unit and DOS COM tests exercise 1/3 rounding, reverse division, comparison
  condition codes and pops, signed zero, 80-bit byte layout, invalid
  operands, and read/write permission failures.

## Explicit limits

This is **not** full 80387 emulation. The supported finite arithmetic
continues to require PC=11 (64-bit significand precision) and
RC=00 (round to nearest/even). IEEE denormals, NaNs, pseudo-denormal m80,
unaligned/unsupported 80-bit encodings, exponent underflow/overflow and
the corresponding masked or unmasked exception delivery are intentionally
not silently simulated. Division by zero and 0/0 currently stop as
unsupported rather than creating infinity/NaN. Other precision-control
settings must be implemented separately.

This phase **does not certify** Turbo Pascal `{$N+}`:
other Pascal runtime instructions, `FLDCW`/`FNSTCW`,
integer conversions, complete exception semantics and
IDE child-process termination may still be needed.

## Regression baseline

The `programs/dos/MANDELFP.PAS` software-Real version (`{$N-}`)
produced `SUM=737` and `WEIGHTED=97090` with the documented
16×16, 32-iteration image. That verified reference and the reported
0.55-second end-to-end time are separate from this unverified x87 path.
