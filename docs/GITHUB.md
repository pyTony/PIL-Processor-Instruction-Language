# Current branch workflow

- dev: full development source, tests, oracles, CI, export/package tools and logs.
- main: runtime source, embedded ISA, build/debug helpers, sample image and user docs.
- Run python3 tools/export_runtime.py EMPTY_DEST --source-ref DEV_COMMIT to prepare
  a delivery. CI uses --verify to prove the exported source is self-contained.
- Commit the exact exported tree on a delivery branch based on main, then open
  its PR. Never merge dev directly into main. Browser approval is followed by
  git switch main; git pull --ff-only origin main on the user's phone.
- Keep the full provenance/revision logs and CLAUDE.md on dev. Main carries only
  its release-specific credits/notes, delivery source revision and checksums.

# Preparing the first GitHub push

The patch prepares a source tree; it does not create a repository, choose
a remote, publish anything or invent a project-wide licence.

The root should contain Cargo.toml, Cargo.lock (generated by Cargo), README.md
and the src/, isa/, tests/, tools/, docs/ directories, plus Git metadata files.
target/ may still exist locally after builds; it is ignored and is not source.
Cargo.lock should be committed for this executable project.

Before the first commit:

```sh
cd ~/pil_proof
cargo test
python3 tools/verify_descriptions.py
python3 tools/verify_flow.py
git init -b main
git add .gitignore .gitattributes Cargo.toml Cargo.lock README.md src isa tests tools docs
git status --short
git diff --cached --stat
```

Run cargo test before staging so Cargo.lock reflects version 0.5.0.
Do not commit target/, Python caches, downloaded disk images, SD-card contents,
secrets, generated binaries or large compiler-test artifacts.

Check docs/REFERENCES_AND_CREDITS.md and decide the distribution licence for
the project's own code before public release. No LICENSE file has been
invented. No third-party emulator code or disk images are bundled.

After reviewing the staged content and choosing the licence, commit it.
Create/select the intended GitHub repository and add its exact remote URL,
then push main. No remote URL or account setting is assumed by this patch.
The authoring environment has not run these Git commands on the user's phone.
